# 故障归因与恢复

先保留失败证据，再按数据、特征、方法、参数、实现或指标归因；没有证据时不直接升级模型复杂度。

| 症状 | 首要检查 | 处理路径 |
|---|---|---|
| 附件缺失、字段或单位不明 | `data_profile`、来源、单位和映射 | `data-auditor-cleaner`；必要时 `modeling-evidence-collector` |
| 验证异常优秀或骤降 | 划分、时点、目标派生特征、预处理拟合范围 | `feature-engineering` / 语言 reviewer，修复后新 run |
| 主方法效果不稳或不如 reference | 比较契约、实现一致性、窗口/种子和风险假设 | `result-evaluator` 归因，再定向修复或结果判断 |
| 优化不可行或不可实施 | 单位、边界、硬约束、残差和最小冲突集 | 对应优化 Skill 与 reviewer；改变题意需人工决定 |
| 参数不可识别、结果随种子波动 | 灵敏度、后验/残差、重复运行和单位 | `robustness-checker`，必要时收窄声明 |
| 学术资料不足 | 已覆盖的机理、适用性、验证与参数依据 | 扩展证据深度；缺全文记录边界，不自动阻止方法选择 |
| 结果展示与结果证据不一致 | 来源定位、哈希和展示检查报告 | 从受影响步骤重跑 → 重新生成 `solution-presentation` |

同一 approved method family 的参数、种子和实现重跑只新增 run ID；方法、数据定义、特征或指标语义改变才由 Git 管理器建立后继分支。
