# 优秀数模论文的论证逻辑

## 经验来源与使用边界

本文归纳自项目中的写作笔记、优秀论文结构与表达指南，以及对 2017、2018、2023、2024、2025 年代表性 CUMCM 优秀论文的抽样检查。样本覆盖统计建模、调度优化、物理机理、几何递推、医学决策和动态网络等任务。

归纳结果用于指导“如何组织当前论文”，不是历年论文评价结论，也不能替代当前赛题的文献、数据和实验依据。不要复刻样本的句式、公式或结论；样本中把大量代码、符号或软件操作放入正文等做法也不应照搬。

## 一条受约束的推理链

优秀数学建模论文的核心不是数学工具最多，而是下列链条完整且可复核：

> 现实任务 → 明确交付物 → 问题特征与困难 → 有边界的简化 → 数学对象 → 匹配结构的方法 → 可复现求解 → 结果、比较与检验 → 直接答案 → 适用范围与局限

全文必须让读者回答六个问题：

1. 题目真正要求交付什么？
2. 现实对象为什么可以被这样简化？
3. 变量、关系、目标和约束如何对应现实？
4. 为什么该模型和算法适合，而不只是“常用”？
5. 哪些数字、图表、比较或检验支持结论？
6. 结论在什么条件下成立，哪些范围不能推广？

任何一环断裂都会形成典型弱点：只有背景没有任务、只有模型名没有结构、只有公式没有现实含义、只有数值没有判断、只有优点没有证据、只有结论没有边界。

## 三次关键转换

### 1. 从题面到问题

不要大段复述题目。把题面转换为：

- 研究对象和状态；
- 每问的输入、输出与评价标准；
- 必须保留的约束和可以简化的因素；
- 数据、时间、空间或资源边界；
- 各问之间的依赖。

转换的成果是“可检查的任务定义”，不是背景摘要。

### 2. 从问题到模型

先写问题特征，再写数学需求，最后写方法性质。例如：

- 存在资源竞争和硬约束 → 需要显式表示可行域 → 使用规划或约束搜索；
- 观测存在重复测量和个体差异 → 需要分离层级变异 → 使用混合效应或层次模型；
- 状态随时间和事件变化 → 需要动态更新 → 使用递推、仿真或时变网络；
- 物理量受几何和守恒关系控制 → 先构建机理关系，再做参数计算或优化。

模型选择句应具有以下结构：

> 由于【问题特征】会导致【数学困难或信息需求】，本文需要【方法能力】；所采用的方法能通过【关键机制】处理该困难，因此适用于本问。

模型名称只能是结论，不能是理由。“经典”“常用”“精度高”均不足以证明适用性。

### 3. 从输出到结论

软件输出不是论文结论。必须完成：

> 适用条件 → 数值或结构结果 → 对照/检验 → 原因或机制解释 → 对题目作答 → 边界

如果不能给出机制性解释，可以明确写成经验性关联、数值现象或决策启示，不能升级为因果规律。

## 全篇结构是一张依赖图

多问赛题通常不是多个独立作业。写作前需识别：

- **共享基础**：数据契约、坐标系、符号、单位、状态定义、评价准则；
- **传递接口**：前问输出的参数、集合、预测、状态或权重如何成为后问输入；
- **新增变化**：后问增加了哪些约束、目标、随机性或现实因素；
- **闭环验证**：后问是否也能反向检验前问假设或模型。

最常见的递进方式是：

- 描述/计算 → 解释/预测 → 决策/优化；
- 基本场景 → 复杂场景 → 故障或不确定场景；
- 单对象 → 多对象耦合 → 动态系统；
- 固定参数 → 参数优化 → 方案比较；
- 静态网络 → 时变网络 → 实时决策。

后续问题采用“继承—修改—求解—比较”：先指出沿用的定义和结论，再说明新因素如何改变模型，随后给出求解和相对前问的结果变化。

## 简化必须有边界

模型假设不是仪式性列表。每条重要假设都要回答：

- 为什么在本题尺度上可以这样假设；
- 它移除了什么复杂性；
- 它影响哪些方程、参数或结论；
- 违反假设时结果可能怎样偏移；
- 是否通过敏感性、情景或误差分析检查过。

假设在模型建立处发挥作用，在评价与局限处被回收。未被模型使用的假设应删除。

## 证据决定主张强度

按证据能力控制措辞：

- 描述统计支持“呈现、集中、差异”；
- 相关或回归支持“关联、解释度、条件性影响”；
- 预测验证支持“在当前划分和预测范围内的误差或稳定性”；
- 对照实验或消融支持“某因素对指标变化的贡献”；
- 优化输出支持“在给定目标、约束和参数下的可行或较优方案”；
- 敏感性和鲁棒性支持“在已测试扰动范围内结论保持”；
- 机理定律与量纲/边界验证支持“模型关系与已知规律一致”。

未检验全局最优，不写“全局最优”；未做因果识别，不写“导致”；未覆盖总体，不写“普遍适用”；只与一个基线比较，不写“优于现有方法”。

## 正文与附录的职责

正文保留会改变读者判断的内容：

- 问题抽象和方法选择理由；
- 核心假设、变量、目标与约束；
- 必要推导和算法机制；
- 关键结果、比较、检验和直接答案；
- 适用范围、局限和推广方向。

附录承载复现细节：

- 完整代码和运行说明；
- 大型结果表、逐行输出；
- 非关键的长推导；
- 补充图、补充检验和中间参数。

不能用“详见附录”隐藏本问最终答案、关键可行性证据或决定性模型关系。

## 何谓真正的整体感

一篇论文具有整体感，不是因为章节标题整齐，而是因为：

- 摘要中的方法和数字能在正文找到依据；
- 问题分析预告的困难在模型中被实际处理；
- 假设和符号贯穿后续推导；
- 算法针对模型结构，而不是独立介绍；
- 结果解释回到原始任务和成功标准；
- 局限对应真实假设和未验证范围；
- 结论与附件结果文件、代码和图表相互一致。

以此为最高写作原则：**论文写的是受证据约束的建模推理，而不是建模过程的流水账。**
