公共规则统一遵循 [项目 AGENTS.md](../../../AGENTS.md)；本 Skill 只补充数学建模论文写作的专业契约。

# 定位

本 Skill 把已经确认的数学建模过程写成一条可检查的论证链，而不是把代码、公式和结果依次粘贴到论文中。写作时同时做到：

- 读者不运行代码，也能理解问题如何被抽象、模型为何适用、算法如何求解、结果为何支持结论；
- 论文中的数字、方法、图表、人工判断和适用边界均能回溯到权威产物；
- 多个小问形成递进的整体方案，而不是互不相干的模型集合。

往年论文与写作指南只提供结构和表达上的经验先验，不能充当当前赛题的事实、参数、引用或效果证据，也不得仿写其句子。

# 使用前提

正式成稿要求：

- `rigor_profile=submission`；
- 最终方法解释、结果分析、鲁棒性证据和已验证图表存在；
- `qx_solution_package_for_writer.md` 与当前 `frozen_numbers.json` 存在；
- 结果接受、声明范围等必要人工决定已经记入 `qx_decisions.jsonl`。

缺少前提时，返回对应产物的生产 Skill，不用模糊语言掩盖证据缺口。用户只要求示范结构、改写无数字段落或制作提纲时，可以在明确标注“非正式草稿”的前提下工作，但不得把占位内容写入正式章节。

# 必读参考

- 每次写作先读 [优秀数模论文的论证逻辑](references/math-modeling-paper-logic.md)。
- 撰写或重写具体章节时读 [分节与题型写作契约](references/section-contracts.md) 中对应部分；完整论文读取全文。
- 交付草稿或审改现有正文前读 [表达与审校清单](references/writing-review.md)。

# 权威来源顺序

按下列优先级取材：

1. `qx_solution_package_for_writer.md`；
2. `frozen_numbers.json`；
3. `qx_decisions.jsonl`；
4. 已验证的论文图表及其 manifest；
5. 最终方法解释、结果报告和鲁棒性报告；
6. 已核验的文献与外部数据注册表。

同一事实发生冲突时停止写入该主张并报告冲突，不从分散的实验目录中挑选更好看的数值，也不自行推断人工选择理由。

# 写作流程

## 1. 确定写作任务

识别比赛、语言、格式、目标章节、篇幅和已有正文。区分三类任务：

- 完整成稿：先搭全篇论证骨架，再逐节写作；
- 单节写作：检查该节与前后章节的接口，避免局部正确而全篇断裂；
- 审改：先保留原意和冻结声明，再修复逻辑、结构与表达，不能借润色改变模型。

## 2. 建立全篇故事线

在动笔前形成内部写作地图：每问的交付物、与前问的继承关系、新增困难、共享数据/状态/符号、核心模型、求解算法、关键证据、直接答案以及通向下一问的接口。

完整论文建议按“问题重述与总分析 → 准备工作 → 各问闭环 → 全局检验与评价 → 摘要与标题”推进。摘要最后写，使其与正文和冻结结果一致。

## 3. 建立主张映射

为准备写入的关键结论确认：

- 主张及适用条件；
- 数值或结构结论的冻结来源；
- 比较对象和统一口径；
- 鲁棒性或不确定性支持；
- 人工决定 ID；
- 图表引用；
- 局限和不能声称的内容。

主张强度不得超过证据强度。相关性结果不得写成因果关系，局部样本结果不得无依据推广到总体。

## 4. 写出每一问的闭环

每个小问都按以下逻辑组织，但不要机械地使用相同小标题：

1. **任务与接口**：本问回答什么，继承前文什么，新增什么困难；
2. **结构与方法**：由题目特征推出数学需求，再由数学需求推出模型或算法的适用性质；
3. **模型化**：说明对象、变量、关系、目标、约束、条件和单位，使问题成为封闭且可求解的数学对象；
4. **求解**：说明算法为何能处理该结构、关键设置和停止/可行性标准，正文不抄代码；
5. **证据与答案**：按“条件 → 结果 → 比较或检验 → 机制解释 → 对题目直接作答”收束；
6. **后续接口**：若下一问复用本问结果，明确传递的状态、参数、集合或评价标准。

后续小问优先使用“继承—修改—求解—比较”的叙事，不重复抄写前问模型。

## 5. 安排公式、图表与附录

- 公式出现前说明要表达的现实关系或求解目的，出现后解释符号、方向、单位、约束意义和下一步用途。
- 每幅图表只承担一个明确的证据任务；正文提出问题、指向证据并解释结论。
- 只使用适合论文展示的 Type 2–4 图；Type 1 调试诊断图不得进入正文。
- 正文保留关键推导、判断和最终证据；代码、长表、重复输出和非关键中间推导放附录。
- 最终答案、关键约束、核心检验和决定性比较不得藏在附录。

## 6. 保存和交接

- TeX 分节草稿写入 `paper/drafts/qx.tex`；由 `paper-polisher` 产出核验后的 `paper/sections/qx.tex`。
- 会话明确选择 Word/Markdown 主格式时，按状态机约定写入 `paper/sections/qx.md`。
- 中文 LaTeX 交给 `latex-paper-zh`；明确的英文 LaTeX 交给 `latex-paper-en`。
- `latex_primary_docx_mirror` 模式下只维护 LaTeX 权威正文，DOCX 由 `latex-paper-zh` 从同一来源派生。
- 引用交给 `reference-manager` 核验；语言润色交给 `paper-polisher`，不得在交接时改动冻结数字。

# 写作边界

- 不重新选择方法、修改算法或重算结果；发现方法叙述与实现不一致时退回对应上游 Skill。
- 不虚构引用、数据、参数、实验、物理意义、创新点或人工理由。
- 不用模型名称、软件名称或“效果良好”等评价替代论证。
- 不把建模过程写成按时间排列的操作日志。
- 基线和淘汰方案只在解释真实决策、比较优势或适用边界时出现。
- 假设必须说明理由和影响，并在局限性中回收重要假设的代价。
- 全篇符号、单位、精度、术语、文件名和图表编号保持一致。
- 不新建人工决定产物。

# 验收

交付前确认：

- 读者能看出“题目特征 → 数学需求 → 方法性质”的选择逻辑；
- 每问都有明确交付物、完整闭环和对题目的直接答案；
- 所有数值与 `frozen_numbers.json` 一致，比较口径一致；
- 公式、符号、单位、算法设置和图表职责均得到解释；
- 结果段同时包含条件、证据、解释和边界，不只报表或报数；
- 多问之间的继承与变化可见，摘要覆盖主要方法和关键结果；
- 局限与不确定性和实际证据相称，无夸大、因果偷换或范围外推广；
- 正文与附录分工合理，Type 1 图未进入论文；
- 交付语言和格式与会话配置一致。
