# 数模实验版本策略

## 稳定线与实验线

- `main` 保存已接受且可复现的状态。
- 实验分支使用 `exp/<contest>/<question>/<algorithm>`，小写并将空格转成连字符。
- 多个算法应从同一个接受 commit 分叉；否则代码差异可以查看，但结果不得默认直接比较。

## 提交边界

一次可复现实验提交应尽量原子化，包含算法代码、配置、契约、精简结果摘要和状态更新。失败实验可以提交，但必须标明失败状态，不得写成成功。

推荐前缀：`checkpoint`、`exp`、`fix`、`accept`、`revert`、`paper`、`audit`。

## 可比契约

至少一致：`question_id`、`data_hash`、`split_hash`、`feature_spec_hash`、`metric_definition_hash`。环境、依赖或随机种子不同必须显式显示；随机算法还应进行多种子或重复实验，而不是只比一个种子。

## 回退

- 未合并的差方案：保留实验分支，切回稳定分支。
- 已合并的差方案：`git revert` 对应提交或合并提交。
- 有未提交改动时停止，不自动 stash、覆盖或删除用户内容。
